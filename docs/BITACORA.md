| 2026-11-12 | Cristhian | Linux (Debian), Python 3.13.5, JDK 17.0.18 | PySpark 4.3.0 exige Python 3.11 o superior; el enunciado dice "3.9 o superior" | Se fija Python 3.11–3.13 y JDK 17 para todo el grupo (decisión D3 del plan) |
| 2026-11-15 | P1 | Windows 11 Home, Ryzen 5 7520U (4C/8T), 15,3 GB RAM, 300 GB libres | Solo había Python 3.14.7 (fuera del rango 3.11–3.13) y el comando `python` abría la tienda Microsoft Store; no había Java ni `JAVA_HOME` | `winget install --id Python.Python.3.13 -e` → Python 3.13.17, y usar siempre el lanzador `py -3.13`. `winget install --id Microsoft.OpenJDK.17 -e` → JDK 17.0.21 (pide elevación UAC). `.venv` creado con `requirements.txt` completo. `SPARK_HOME` no hace falta: PySpark se instala con Spark incluido |
| 2026-11-15 | P1 | Windows 11 Home (mismo equipo) | Escribir Parquet falló en dos pasos: primero `Shell.checkHadoopHome` (no existía `HADOOP_HOME`) y después `UnsatisfiedLinkError: NativeIO$Windows.access0` (faltaba `hadoop.dll`) | `scripts/setup_winutils.ps1`: crea `%LOCALAPPDATA%\hadoop\bin`, descarga `winutils.exe` (SHA-256 `496A591E…EFD8553`) y `hadoop.dll` (SHA-256 `D7AB36A6…0405BE3`) de Hadoop 3.3.6, verifica el hash y define `HADOOP_HOME` + `PATH` de usuario. Con eso: `pytest -q` → **todas las pruebas pasan**. PySpark 4.3.0 trae el cliente Hadoop 3.5.0 y la interfaz nativa es compatible con 3.3.6 |
| 2026-11-15 | P1 | Windows 11 Home (mismo equipo) | El script `setup_winutils.ps1` no arrancaba: `throw "$name: ..."` es un error de parseo fatal en PowerShell (el `:` debe ir seguido de un nombre de variable válido) | Usar `throw "${name}: ..."`, guardar el archivo como UTF-8 **con BOM** (PowerShell 5.1 lee un UTF-8 sin BOM como ANSI y rompe los acentos) y añadir `tests/test_scripts_syntax.py`, que lo comprueba en cada corrida. `pytest -q` → **6 pruebas pasan**. Detectado por la revisión independiente del entregable, no por el autor |
